# Smart Bag IoT

IoT proof-of-concept combining an ESP32 sketch and a browser-based simulator/logger for GPS, weight, and Bluetooth anti-loss. The web interface also simulates GPS spoofing attacks with visual + audible alarms.

## Repository structure

- `esp32-code/` — Arduino sketch (`smart_bag.ino`) with simulated weight sensor, GPS drift, anti-theft buzzer, and Bluetooth anti-loss logic.
- `web-interface/` — Frontend simulator (HTML/CSS/JS) plus Node/Express logger that writes GPS/RSSI/weight events to MongoDB.
- `package-lock.json` — Generated by npm for the web interface logger.

## Prerequisites

- Node.js 18+ and npm
- MongoDB running locally or accessible via connection string (optional if you only demo the UI)
- Browser with audio output (user interaction required to unlock sound autoplay)

## Quick start (web interface + logger)

1. `cd web-interface`
2. `npm install`
3. Create a `.env` (optional) to override defaults (local-only by default):
   ```env
   PORT=3001
   # Local dev example
   MONGO_URI=mongodb://localhost:27017
   # MongoDB Atlas example (replace user/pass/host)
   # MONGO_URI=
   DB_NAME=smartBag
   DISCOVERY_PORT=4210
   DISCOVERY_TOKEN=SMARTBAG_DISCOVER
   ```
4. Start the logger/static server:
   ```bash
   npm start
   ```
5. Open `http://localhost:3001` in your browser.

### Local MongoDB only (recommended for offline dev)

1. Installe MongoDB Community Edition (https://www.mongodb.com/try/download/community) et démarre le service `mongod` (Windows : `net start MongoDB`).
2. Laisse `MONGO_URI=mongodb://localhost:27017` dans `.env`.
3. Tu peux vérifier que la base est créée automatiquement avec `mongosh` :
   ```powershell
   mongosh "mongodb://localhost:27017" --eval "db.getMongo().getDBNames()"
   ```
4. Lance `npm start`; le serveur Express loguera désormais dans `smartBag` localement (aucun accès Internet requis).

### Automatic ESP32 discovery

- `server.js` also starts a tiny UDP service on port `4210` that replies `SMARTBAG_API=http://<ip>:<port>` whenever it receives `SMARTBAG_DISCOVER`.
- The ESP32 broadcasts this request right after joining Wi-Fi, so it learns the correct base URL even if your PC changes IP.
- If the discovery packets sont bloqués (pare-feu, sous-réseaux différents), either open UDP `4210` or set `API_BASE_URL_OVERRIDE` in the sketch as a fallback.

## Using MongoDB Atlas (recommended for cloud demos)

1. **Create a cluster**: log into [MongoDB Atlas](https://cloud.mongodb.com/), create a free/shared cluster (M0) in a region close to you.
2. **Create a database user**: go to *Database Access* → *Add New Database User*. Choose *Password* auth, set an app-specific user/password, and restrict privileges to the `smartBag` database if desired.
3. **Allow your IPs**: in *Network Access*, add your public IP (or `0.0.0.0/0` for quick testing—remember to tighten later). Each ESP32/device pushing through your router will share the same public IP.
4. **Grab the connection string**: in *Database Deployments* → *Connect* → *Drivers*, copy the `mongodb+srv://...` URI. Replace the placeholder password and optional default database in the string.
5. **Update `.env`**: set `MONGO_URI` to the Atlas URI and keep `DB_NAME=smartBag` (Atlas automatically creates it on first write). Make sure `.env` stays out of version control.
6. **Restart the logger**: `npm start`. The console should now display `💾 MongoDB: mongodb+srv://.../smartBag`. If authentication fails, double-check the user/password and IP allow list.
7. **Verify writes**: in Atlas, open the *Collections* tab and watch `Poids`, `GPSLogs`, `BluetoothRSSI` fill up as soon as the ESP32 or the web simulator sends telemetry.

Security tips:
- Use long, random passwords and rotate them periodically.
- For production, prefer *Custom Roles* that only allow inserts/reads the app truly needs.
- Consider VPC peering/private endpoints instead of `0.0.0.0/0` once you move past the prototype stage.

## Using the web simulator

- **Bag weight & reference**: drag items into the bag or use the selectors; set a reference weight; alerts fire when weight deviates beyond tolerance.
- **Bluetooth anti-loss**: move the phone/bag components on the canvas; RSSI falls with distance and triggers connection-lost visuals.
- **GPS tracking**: bag position drives lat/lng; map dot updates and logs to Mongo.
- **Silence alarm**: the ✓ button on the bag stops the LED + sound.
- **Simuler Attaque GPS**: bottom-right red button jumps the GPS ~2 km away, logs an `attackType=gps_spoofing`, and now triggers both visual and audible alarms.

## Data logged (MongoDB)

- `GPSLogs`: `deviceId`, `latitude`, `longitude`, `vitesse`, `distanceFromHome`, `zoneAlerte`, `attackType?`, `createdAt`
- `BluetoothRSSI`: `deviceId`, `rssi`, `signal`, `alerte`, `createdAt`
- `Poids`: `deviceId`, `poidsActuel`, `poidsRef`, `ecart`, `alerte`, `createdAt`

## ESP32 sketch (`esp32-code/smart_bag.ino`)

- Simulates load-cell input via potentiometer, compares against `POIDS_REF` with `TOLERANCE`.
- Blinks LED and drives buzzer on weight anomalies, movement (GPS drift), or Bluetooth RSSI drops below `seuil_oubli`.
- Connects to Wi-Fi (update `WIFI_SSID` / `WIFI_PASSWORD`) and pushes telemetry every 5 seconds to the Node/Express logger via HTTP POST (`/api/logs/poids`, `/gps`, `/rssi`).
- Automatically discovers the API base URL via UDP broadcast (port `4210`). The Node server answers `SMARTBAG_API=http://<ip>:<port>` and the ESP32 caches it. No manual edit is needed anymore. If you really need a static override, set `API_BASE_URL_OVERRIDE` in the sketch.
- Prints telemetry + HTTP status codes over Serial at 115200 baud for easy debugging.

### Étapes pour tester l’ESP32 avec le backend

1. Démarrer le logger (`npm install && npm start` dans `web-interface/`).
2. Assure-toi que le pare-feu autorise UDP entrant/sortant sur le port `4210` (découverte) et TCP sur `3001` (API).
3. Ouvre `smart_bag.ino` et ne modifie que `WIFI_SSID` / `WIFI_PASSWORD` si nécessaire (l’API se découvre seule). Optionnel : renseigne `API_BASE_URL_OVERRIDE` pour forcer une adresse spécifique.
4. Compiler / téléverser sur l’ESP32 (ou lancer la simu Wokwi). La console série affichera `[DISCOVERY] API trouvée : http://192.168.x.x:3001`, puis les POST successifs; côté serveur tu verras `📥` + la collection ciblée.

## Development tips

- Run with `npm run dev` for auto-restart of the logger via nodemon.
- Audio: browsers block autoplay; click once (pointerdown) to prime the audio context.
- If Mongo is unavailable, the UI still works; log POSTs will fail silently in the console.

## Troubleshooting

- **Port already in use**: change `PORT` in `.env` or stop the conflicting service.
- **No alarm sound**: interact with the page once to allow audio; ensure system volume is up.
- **No Mongo writes**: verify `MONGO_URI`, `DB_NAME`, and that the Mongo service is running.
